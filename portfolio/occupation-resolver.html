The occupation resolver

Any messy employer job title, resolved to a federal occupation code and a recruiter-legible canonical name.

DisciplinesMachine learning · LLM systems · information retrieval · data engineering

Runs on employer HRIS panels and public postings under tenant isolation. The sample here is synthetic so you can try it.

The problem

Employers name the same job a hundred ways: "AmbFloat LPN / II", "RN/Care Manager", "Sr. Scrum Master (Remote, LOCALS)". Nothing downstream, no benchmark, no forecast, no career transition, works until those titles collapse onto one federal spine. And there is no ground truth to check against: no labelled set says which code is correct. Getting this stage right, cheaply and honestly, is what makes everything after it possible.

How it works

01
One job, a hundred names

Raw titles carry shift tags, unit codes, seniority markers, and location suffixes, all noise before anything can be judged. The first move is to strip and normalise the input so that what remains is the job, not the paperwork around it.

Information retrieval · data engineering

02
Spend certainty cheaply

A ten-stage cascade resolves what it can at each step and passes only the residual on: exact caches and keyword rules first, then O*NET substring and embeddings, then the models. Each stage has a confidence floor, and nothing passes below its floor. The figure below is the residual after each stage.

Information retrieval · data engineering

03
Three models, called in sequence

An open-source embedding baseline handles the well-behaved majority for free. A fine-tuned in-domain encoder carries the ambiguous middle. A local, tenant-isolated LLM adjudicates the long tail, novel titles, marketing-speak, compound roles, with JSON-constrained output.

Machine learning · LLM systems

04
Labels without a labelled set

With no gold standard to train on, labels are generated by a locally-run LLM over normalised employer extracts, then reviewed, turning an unlabelled problem into a supervised one at scale. That generated corpus is what the in-domain encoder learns from.

LLM systems · data engineering

Resolve a title type or pick

Any employer title, two outputs: a canonical name a recruiter recognises, and the federal SOC-6 code. The margin says which layer answered.

What's real

The resolver you can try above matches against a small synthetic sample. In production the same input runs the three model layers with the ten-stage cascade in front, over employer HRIS panels and public postings, with inference kept under tenant isolation. Every number a title becomes is traceable back to the stage that produced it, and titles with no confident match are flagged for review rather than forced. All data shown here is illustrative and synthetic.
