Occupational coding at the 8-digit frontier

Every labor dataset built from job titles has to map messy strings onto an occupation code. At the 6-digit level this is close to solved. At the 8-digit level, where wage, task, and mobility differences actually live, it is much harder, and the method you pick changes the answer.

Machine learning · measurement. A benchmark study with a public evaluation harness.
01

The idea

The 8-digit code is where an acute-care nurse is separated from a clinical nurse specialist, and that is exactly the grain a wage or mobility study needs. Two families of method compete for it: retrieval, which searches a corpus of known titles for the closest match, and classification, which learns a decision boundary from labeled examples. Teams reach for retrieval and for fine-tuned models by default. A systematic comparison on a hard evaluation set shows both defaults are wrong.

02

The bakeoff

Hold the evaluation fixed and compare like for like: an oracle retrieval ceiling, which always surfaces the true code if it is anywhere in the candidate set, a frozen encoder with a linear probe, LoRA fine-tuning, full fine-tuning, and the production cascade. The same hard set, the same splits, the same metric. The oracle matters because it is the best any retrieval system could ever do, so it turns a comparison into a bound.

03

Findings

01
Retrieval has a ceiling that classification clears.
The oracle retrieval system tops out at 40.4 percent on the hard set, while a trained classifier reaches 45.5 percent top-3. Retrieval is bounded by whether the corpus holds a phrasing close to the input. A classifier learns the boundary whether or not the phrasing was ever seen.
02
More trainable parameters overfit at real data scales.
At about 17,000 labeled examples, a frozen encoder with a linear probe reaches 45.5 percent, LoRA fine-tuning 42.4 percent, and full fine-tuning 32.3 percent. Performance falls monotonically as trainable capacity rises. The practical instruction is to freeze and probe, and to spend on labels rather than parameters.
03
The production answer is a cascade.
Cheap high-precision matching resolves the easy majority, and a frozen-and-probed classifier carries the residual that retrieval leaves behind. That residual is where the accuracy is won or lost, which is why the choice of method there matters so much. The system in production runs exactly this shape, in the occupation resolver.
04

What is next

The result becomes a benchmark other teams can use. That means one clean re-run with fixed splits, three seeds, and bootstrap confidence intervals, so every number carries an interval. It means measuring corpus coverage directly, which turns the 40.4 percent ceiling from an observation into an explanation by separating what retrieval cannot reach from what it merely ranks wrong. And it means releasing the evaluation harness, so anyone building an occupational coder can run it against the same hard set and see where they stand.
