Reading the Beige Book with LLMs

Eight times a year the twelve Federal Reserve districts publish qualitative reports full of labor-market detail. Economists have mined them with dictionaries and hand-coding for decades. An LLM extracts structured labor sentiment from each release for about thirteen cents, so the full forty-year archive can be processed for a few hundred dollars.

Economics · LLM systems · data engineering. A short methods note with a public dataset attached.
01

The idea

The Beige Book is a rich account of hiring difficulty, wage pressure, and labor availability, district by district. Dictionaries miss context and hand-coding does not scale, so the text has never been turned into a clean, continuous labor-market series. An LLM reads each district report under a fixed extraction schema and returns structured signals, cheaply enough to run the entire modern archive. The cost is part of the point: at thirteen cents a release, the economics of turning text into data change.

02

The approach

Freeze the schema (labor tightness direction, wage pressure, sector mentions, and a confidence field) and document the exact prompt, since replicability is the whole selling point. Run it across the full archive, one row per release and district, and publish that file as the deliverable. Validate three ways: internal reliability by rerunning samples and cross-checking a second model, a human-coded benchmark on a stratified subsample, and external validity against hard district data like unemployment and job openings.

03

Findings

01
The pipeline runs, and it is cheap.
Extraction costs about thirteen cents a release, which puts the full historical backfill in the range of a modest one-time run. The output is a release-by-district panel of labor sentiment, and that dataset is the contribution as much as the analysis around it.
02
The validation is what earns the citation.
The Beige Book has an existing literature of dictionary-based indices to benchmark against, so a clean, replicable, LLM-based version with a public dataset and a documented prompt is exactly what the text-as-data genre rewards.
04

What is next

The core work is validation and release: complete the historical backfill, hand-code a stratified sample and report agreement, and check prompt stability across paraphrases and a second model. The test that would make the index useful is whether it turns before the hard data, so the district tightness series is lined up against unemployment and job openings around past downturns to see if the words lead the numbers. The dataset, the extraction code, and the prompts ship together as a replication pack.
